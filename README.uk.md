## Навіщо це

Джерело — один JSON-файл, який перезаписується при кожному оновленні. У ньому
**вісім рядкових полів і жодного поля статусу**. З цього випливає дві речі, і
саме вони є причиною існування проєкту:

1. **Життєвий цикл запису невидимий.** Немає ознаки «знайдено» чи «закрито».
   Єдиний спостережуваний сигнал завершення справи — запис перестає з'являтися
   у файлі, а цього не видно з жодного окремого завантаження.
2. **Семантику полів втрачено.** Чинна JSON-схема викинула `title`, які були в
   архівній схемі МВС, лишивши вісім трилітерних абревіатур (`nz`, `nk`, `dk`,
   `dtl`) без документації будь-де.

Ця версія відновлює історію з власного архіву ревізій порталу, повертає втрачену
семантику й нормалізує два поля, що несуть інформацію про пристрій: вільний
текст марки/моделі та IMEI.

## Що додано

| | Джерело | Ця версія |
|---|---|---|
| Історія запису | немає — файл перезаписується | `first_seen`, `last_seen`, `disappeared_at`, `revision_no` по 1 776 згорнутих знімках із 2019-07-15 |
| Значення полів | недокументовані абревіатури | відновлено з архівної схеми МВС |
| Марка / модель | одне текстове поле, 110 415 написань | розібрані `brand` + `model`, виправлено змішування абеток |
| IMEI | сирий рядок різної довжини | 15-значний `imei_norm`, `tac`, `rbi`, перевірка Луна, ознака ремонту |
| Дати | формально ISO, але сягають 0201 року | перевірені, неправдоподібні занулені **й полічені** |
| Дублікати | 7 655 повторених `id` у публікації МВС | дедупліковано в кожному знімку |
| Якість | не звітується | DQ-звіт на кожен прогін, блокує на структурних дефектах |

## Чого це коштувало і що вийшло

Сім років реєстру, зібраних із власного архіву ревізій порталу. Кожне число тут
походить із `wantedmt volume` і самого стану, тому воно перераховується після
будь-якого прогону, а не старіє в прозі.

| | |
| --- | --- |
| Оброблено ревізій | **1 825** (2019-07-15 … 2026-08-01) |
| Прочитано рядків | **1 844 634 671** |
| Опубліковано порталом | **536.05 ГБ** |
| Завантажено | 522.98 ГБ |
| Не качали — хеш уже був відомий | 12.60 ГБ |
| **Збережено на диску** | **0.49 ГБ** — 0.092% від джерела |
| Знімків, що потребували структурного ремонту | 290 |

Похідний набір приблизно в тисячу разів легший за файли, з яких він зроблений, а
будь-який минулий день усе одно відбудовується з parquet-журналу змін, нічого не
качаючи.

### Чого джерело сказати не могло

| | |
| --- | --- |
| Записів бачено взагалі | **1 186 719** |
| Присутні в поточній публікації | 1 062 497 |
| **Закриті — зникли з реєстру** | **124 222** |
| Пішли й повернулись | 21 514 |

Закриті записи — і є сенс усього. Їх немає у файлі, який портал віддає сьогодні,
тож без цієї історії про них не можна сказати нічого: ні що вони існували, ні
коли припинили.

### Розпізнавання

| | Джерело | Ця версія |
| --- | --- | --- |
| **Марка** | вільний текст, 110 415 написань | **99.7%** |
| **Модель** | вільний текст | **96.9%** |
| Область підрозділу реєстрації | вільний текст | 99.6% |
| IMEI придатний до роботи | — | 99.6% |
| IMEI проходить перевірку Луна | — | 83.6% |

Марка й модель приходять із поля, куди писали хто як хотів: `SAMSUNG`,
`САМСУНГ`, `XІAOMІ` з кириличними двійниками, і 126 451 запис, у якому немає
нічого, крім назви виробника. Там, де текст не називає моделі, її називає
IMEI — TAC ідентифікує апарат за стандартом GSMA, і саме це піднімає
розпізнавання моделі з 52.7% до 96.9%.

## Заміряні факти

Усе нижче — з живих даних, не з припущень. Повні числа й запити за ними; кожен
документ існує двома мовами:

| Документ | Українською | English |
| --- | --- | --- |
| Як зібрано набір | [methodology.uk.md](docs/methodology.uk.md) | [methodology.md](docs/methodology.md) |
| Що не так із джерелом | [source_defects.uk.md](docs/source_defects.uk.md) | [source_defects.md](docs/source_defects.md) |
| Звіт профілювання | [profiling_report.uk.md](docs/profiling_report.uk.md) | [profiling_report.md](docs/profiling_report.md) |

- **83.6%** повнорозмірних IMEI проходять перевірку Луна — решта містять описку
  або перебитий ідентифікатор
- до **26.7%** записів бренду ховається за однією кириличною літерою-двійником
  (`HUAWEІ` проти `HUAWEI`, `XІAOMІ` проти `XIAOMI`)
- **83 344** різних префікси TAC
- дати на 100% відповідають ISO-8601 за *формою*, але `dk` сягає **0201** року
- реєстр був **заморожений на 188 днів** у 2020–2021: портал віддав один і той
  самий файл дев'ятнадцять разів, і зарахувати їх як відліки означало б
  стверджувати, що крадіжки телефонів припинились на цілу зиму
- публікація спинилась **2022-02-23**, напередодні повномасштабного вторгнення, і
  відновилась через 177 днів файлом, у якому немає нічого зареєстрованого після
  лютого. Сама реєстрація в березні 2022 впала до **5%** від січневої, а
  Херсонська область за наступні дванадцять місяців звітує **нуль** записів

## Встановлення і запуск

```bash
uv sync

uv run wantedmt timeline                 # знайти всі ревізії обох джерел
uv run wantedmt backfill                 # згорнути їх хронологічно, від найстарішої
uv run wantedmt normalize                # перебудувати IMEI + бренд/модель
uv run wantedmt dq                       # перевірки якості + звіт
uv run wantedmt unmatched --out docs/unmatched.md   # тижнева черга на розбір
uv run wantedmt export --out data/export # parquet + агрегації для публікації
uv run wantedmt lookup-export --out data/lookup   # НЕ для публікації, див. нижче
```

`lookup-export` пише дві проєкції, на яких стоїть безкоштовна перевірка IMEI на
trofey.app: рядок на кожен розшукуваний номер і повний словник TAC. Їх свідомо
немає ні в `manifest.json`, ні в жодному релізі — цей словник містить каталог
під ліцензією MIT, який нам можна використовувати, але не можна перевидавати.
Файли їдуть в одну базу і більше нікуди.

Щоденний прогін згортає лише нове:

```bash
uv run wantedmt watch --source npu    # один запит до API: чи портал попереду нас?
uv run wantedmt daily --source npu && uv run wantedmt normalize && uv run wantedmt dq --publish
```

`watch` виходить із кодом 0, коли є день до згортання, і 3, коли немає, — саме
це читає [.github/workflows/watch.yml](.github/workflows/watch.yml). Його
розклад заміряний, а не вгаданий: із 89 ревізій НПУ **66 припали на
10:30–10:39 UTC**, а вікно 10:30–15:00 покриває 98.9% — і день тижня ролі не
грає, тому перевірки йдуть і у вихідні.

## Як це працює

```
data.gov.ua CKAN                    ┌──────────────┐
  resource_show ──► індекс ревізій  │  1 776 денних│
                                    │    знімків   │
                                    └──────┬───────┘
                                           │ по одному, хронологічно
                                    ┌──────▼───────┐
                                    │ згортка SCD2 │  first_seen / last_seen /
                                    │              │  disappeared_at / revision_no
                                    └──────┬───────┘
                                           │ сирий файл одразу видаляється
                                    ┌──────▼───────┐
                                    │ нормалізація │  IMEI · TAC · марка · модель
                                    └──────┬───────┘
                                    ┌──────▼───────┐
                                    │  DQ + export │  звіт → R2 → trofey.app
                                    └──────────────┘
```

**Сирого шару не зберігаємо — свідомо.** Зберігати всі 1 776 знімків — це ~45 ГБ
parquet, єдине призначення яких — переобчислити ту саму історію. Кожен знімок
вливається в стан і одразу видаляється. Компроміс названий прямо: зміна логіки
згортки означає перекачування, а не переобробку з диска. Трафік дешевий і
повторюваний, холодне зберігання набору під CC-BY себе не окупає.

## Довіра до `disappeared_at`

Зникнення — єдиний сигнал закриття, який дає реєстр, і ми ставимось до нього як
до **свідчення, а не істини**. Запис може зникнути тому, що телефон знайшли — або
тому, що виправили описку, перекласифікували справу чи збився експорт.

Два запобіжники, обидва заміряні, а не вгадані:

- знімок, що втратив **понад 2%** реєстру, фіксується, але **не має права нічого
  закрити** (реєстр зростав монотонно за весь заміряний період; масове падіння —
  це збій публікації, а не масове розкриття);
- зникнення рахується **лише всередині серії одного видавця**. На переході
  МВС→НПУ відсутність означає «мігрувало», а не «знайдено», і застосувати її
  означало б поставити фальшиве масове закриття на дату переходу.

## Обмеження

- **Не в реальному часі й не авторитетно.** Набір відображає те, що видавець
  вивантажив, і коли вивантажив. Пристрій, якого тут немає, може бути
  викраденим; пристрій, який тут є, могли вже повернути.
- **Персональних даних немає.** Усі поля стосуються пристрою або підрозділу
  поліції. Нічого, що це змінює, не додається, і ніщо тут не ідентифікує людей.
- **`disappeared_at` — проксі**, а не підтверджене закриття справи (див. вище).
- **Провалені перевірки Луна звітуються, але не «лікуються».** Переписати цифру
  заради контрольної суми означало б вигадати дані.
- **Покриття TAC часткове.** `TAC_UNKNOWN` — легітимний третій стан, а не
  «недійсний»: будь-яка справді нова модель рік-два невідома безкоштовним
  довідникам TAC.
